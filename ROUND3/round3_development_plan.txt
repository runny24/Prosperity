High-Level Strategy Split
-------------------------
We split Round 3 into five strategy groups:

1. HYDROGEL_PACK spot strategy
   - Independent product.
   - Use simple fair value estimation and conservative market making / mean reversion.
   - Average spread is large, so avoid aggressive overtrading.

2. VELVETFRUIT_EXTRACT spot strategy
   - Independent spot product.
   - Also acts as the underlying price source for all VEV vouchers.
   - Use fair value estimation, inventory-aware quoting, and possibly short-term mean reversion.

3. Deep in-the-money voucher strategy
   Products:
   - VEV_4000
   - VEV_4500
   - VEV_5000

   Idea:
   - These vouchers behave almost like spot minus strike.
   - Fair value is close to:
     max(VELVETFRUIT_EXTRACT_fair - strike, 0) + small_time_value

   Trading:
   - Buy voucher when ask is sufficiently below fair value.
   - Sell voucher when bid is sufficiently above fair value.
   - Use wide thresholds for VEV_4000 and VEV_4500 because spreads are large.

4. Middle voucher relative-value strategy
   Products:
   - VEV_5100
   - VEV_5200
   - VEV_5300
   - VEV_5400
   - VEV_5500

   Idea:
   - These vouchers contain meaningful time value.
   - Cannot price them using intrinsic value only.
   - Build a fair-value function based on:
     spot price, strike, moneyness, TTE, and historical relationship.

   Trading:
   - Buy when voucher is underpriced versus model fair value.
   - Sell when voucher is overpriced versus model fair value.
   - These are likely the highest-value research targets.

5. Far out-of-the-money voucher special handling
   Products:
   - VEV_6000
   - VEV_6500

   Idea:
   - Historical mid price is constant at 0.5.
   - Bid is usually 0 and ask is usually 1.
   - Historical trades occur at 0.

   Trading:
   - Do not use a normal pricing model.
   - First baseline can ignore these products.
   - Optional later rule: buy only if available at 0, avoid buying at 1 unless a clear edge is found.

Phase 3: Implement Baseline Trader
----------------------------------
Deliverable:
- r3_v1.py

Purpose:
- Produce a valid Round 3 trading algorithm that can run on the Prosperity-style platform.

Core structure:
1. Implement Trader.run(state).
2. Parse current order depths.
3. Estimate fair value for each product.
4. Generate orders within position limits.
5. Make position-aware decisions.
6. Return orders, conversions, and traderData if required by the framework.

Product limits:
- HYDROGEL_PACK: 200
- VELVETFRUIT_EXTRACT: 200
- Each VEV voucher: 300

Baseline fair values:
1. HYDROGEL_PACK
   - Use current mid price if available.
   - Optionally use rolling fair value stored in traderData.
   - Trade only when best bid / ask deviates enough from fair value.

2. VELVETFRUIT_EXTRACT
   - Use current mid price as immediate fair value.
   - Optionally smooth with short rolling mean.
   - This fair value becomes underlying spot S for voucher pricing.

3. VEV_4000 / VEV_4500 / VEV_5000
   - fair = max(S - strike, 0) + fixed_time_value
   - Suggested initial fixed_time_value:
     VEV_4000: 0
     VEV_4500: 0
     VEV_5000: 5

4. VEV_5100 / VEV_5200 / VEV_5300 / VEV_5400 / VEV_5500
   - fair = historical time-value table or simple curve by strike.
   - Suggested initial average time values:
     VEV_5100: 17
     VEV_5200: 45
     VEV_5300: 47
     VEV_5400: 16
     VEV_5500: 7
   - fair = intrinsic + estimated_time_value

5. VEV_6000 / VEV_6500
   - Ignore in first baseline.

Trading rule:
- If best ask < fair - buy_threshold:
  buy up to available ask volume and remaining position limit.
- If best bid > fair + sell_threshold:
  sell up to available bid volume and remaining short capacity.
- Threshold should depend on product spread.

Risk controls:
- Never exceed position limit.
- Reduce order size as current inventory approaches limit.
- Use smaller size for model-based voucher trades than for clear arbitrage trades.
- Avoid trading products with missing order book data.

Phase 4: Build Local Backtester
-------------------------------
Deliverable:
- round3_backtester.py

Purpose:
- Evaluate strategy logic against historical order book snapshots before submitting.
- This phase is now mandatory before further serious strategy work because manual platform-only iteration is too slow for a 150000+ target.

Simple backtest assumption:
- At each timestamp, strategy sees current order book.
- If strategy sends a buy order at or above best ask, assume it fills at best ask up to visible volume.
- If strategy sends a sell order at or below best bid, assume it fills at best bid up to visible volume.
- Track cash, positions, and mark-to-market PnL.

Tasks:
1. Load historical price data.
2. Replay timestamps in order.
3. Build a simplified TradingState-like object.
4. Call Trader.run(state).
5. Simulate fills.
6. Track:
   - cash
   - position
   - mark-to-market value
   - total PnL
   - per-product PnL
7. Output performance summary and plots.
8. Run parameter sweeps for voucher strategies.
9. Output per-product PnL, max drawdown, final positions, and trade counts.
10. Support comparing multiple trader files or strategy parameter sets.

Important limitation:
- Historical order books do not guarantee our orders would actually fill in the real competition.
- Backtest is mainly for sanity checking and comparing strategy variants.

Status:
- Completed first version as round3_backtester.py.
- It supports:
  - loading trader .py files
  - injecting a minimal datamodel stub
  - replaying day 0, day 1, day 2, or all days
  - immediate crossing-fill simulation
  - final equity, max/min equity, max drawdown, positions, fills, and per-product PnL
- Known limitation:
  - passive platform fills are not simulated, so platform PnL can differ substantially.
  - use it for ranking and risk direction, not exact score prediction.
